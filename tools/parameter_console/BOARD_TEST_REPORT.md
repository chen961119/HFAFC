# 参数功能板上测试

日期：2026-10-07。设备：Teensy 4.1，COM4，USB 序号 17564410。
配置：`F-TEAM-7-INDI-EXP`，参数表 75 项。

## 结果

| 检查项 | 实测结果 |
| --- | --- |
| 完整读取及分片命令 | BEGIN、75 条 VALUE、END 数量一致，名称无重复 |
| 普通十进制 | 全部值和范围不含科学计数法；浮点写入确认返回 `0.00002` |
| 输入校验 | 超出范围、NaN、Inf、整数小数输入、rev=0、未知名称均被拒绝；拒绝后参数不变 |
| int 写入 | `usb_throttle_debug` 从原值 1 临时改为 0，收到 `int / SAVED` |
| float 写入 | `Kd_roll_angle` 从原值 1 临时改为 `0.00002`，收到 `float / SAVED` |
| 写后读取 | 连续 3 次全表读取，与预期 float32/int32 值一致 |
| SD 保存及读回校验 | 写入收到 SAVED；实际固件关闭文件后读回检查 CRC、类型、范围和值 |
| 断电上电恢复 | 用户完整断电再上电后返回 `SD_READY / LOADED`，全部 75 项与保存值一致 |
| 测试值清理 | 原始全部参数已恢复到 RAM 和主文件；再提交一次原值，使备份也不含临时测试值 |

75 项全表读取实测约 0.34～0.63 秒；包含 SD 主文件/备份保存和读回校验的写入确认约 1.09～1.44 秒。该时间为电脑发送到收到确认的耗时，尚未独立测量各个 SD 操作与控制周期耗时。

## 发现的问题与范围

重新烧录后的启动出现过 `NO_SD / DEFAULTS`。增加了仅在启动时执行的 3 次 SD 初始化尝试，间隔 100 ms；本次仍需要完整断电再上电后才恢复 SD。**不能据此宣称重新烧录后的 SD 初始化问题已修复。** 初始化失败时停止日志文件打开流程，参数服务拒绝写入。

本次实测没有拔卡制造写入故障，也没有破坏 SD 文件进行恢复测试；短写、坏 CRC、主文件损坏回退和 512 项容量由主机模拟测试覆盖。板上目前注册的是 75 项。

原始参数快照、测试记录和串口原始字节保存于仓库的 `.pio/board_parameter_test/`，不进入 Git。测试后释放了 COM4。
