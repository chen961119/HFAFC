# 统一参数与持久存储

飞机编号和总数已经从编译宏改为参数。同一硬件、接收机及控制算法配置下，A～G 可以刷同一个固件。

## 第一次使用

1. USB 连接地面站，在“飞机设置 → 参数”读取参数。
2. 设置 `aircraft_count`，支持 1（单机）、3、4、5、7；再设置 `aircraft_id`，1=A，2=B，…，7=G。编号不得超过数量。减少数量前先降低编号。单机使用数量 1、编号 1。
3. 使用通讯连接页“重启飞控”或断电重启，重新连接并读取参数，确认本机身份。
4. 完成 IMU 校准，确认 `imu_calibration_valid=1`。没有有效身份或 IMU 校准时禁止解锁。

新板的编号默认 0（未配置），数量默认 3。保存身份只改变待启动值，主循环始终使用启动时锁定的身份和数量；运行中改编号不会改变串口路由或控制分配。

数量 1 在重启后选择单机混控，本机 IMU 滚转角及角速度作为反馈，停止构型控制与机间收发，使用 `loggerSINGLE()` 和对应单机 CSV 表头。其他支持的数量使用编队路径及 `loggerTEAM()`；同一份固件不需要切换单机/编队宏。

单机和多机使用同一套参数声明、默认值与存储。已保存的参数按名称和类型恢复；没有保存值时使用注册变量的初始化值。切换飞机数量不会重置或替换控制增益。

## 参数声明

在 `src/control_modes.cpp::controlParameterTable()` 一处注册，变量仍归各模块所有：

```cpp
{1001, "aircraft_id", &aircraftIdParameter, 0, 7, "Aircraft", "Identity",
 ParameterStorage::EEPROM, ParameterEffect::Reboot},
```

每条声明包含内部 ID、名称、变量地址、范围、分组、说明、存储介质、生效时机和只读标记。浮点参数绑定 `float`，整数参数绑定 `int32_t`；省略最后的选项时默认 SD、立即生效、可编辑。

修改存储位置只需改 `ParameterStorage::EEPROM` / `ParameterStorage::SD`。两种介质均以名称和类型匹配，内部 ID 仅用于模块查找，不写入新记录。新增参数用新名称及未使用的内部 ID，变量初始化值作为默认值。改表顺序或内部 ID 保留已有值；改名视为新参数，使用默认值；类型变化、超界旧值单项回默认值。删除的旧项在成功保存当前快照时移除，不设置删除状态。

名称上限在 `include/parameter_storage_config.h` 的 `COFLY_PARAMETER_NAME_LIMIT` 配置，默认 **32**，也可通过编译选项 `-DCOFLY_PARAMETER_NAME_LIMIT=48` 覆盖。允许 1～128；使用 ASCII 字母、数字、下划线。现有名称完整保留，最长 29。超过配置的注册名称会拒绝初始化，不能静默截断。读取兼容上限固定为 128，地面站也接受到 128，因此调整固件上限无需重编地面站。

上限增大不会改变存储布局，也不会为每项增加固定填充。减小上限前应确保当前注册名称均符合新上限；历史文件中更长的未知名称仍可校验、跳过，不导致整份快照失效。

目前共 75 项：原有 57 项在 SD；新增 18 项默认在 EEPROM，包括飞机编号/数量、12 个 IMU 零偏、校准有效标记、校准模型标记、整组指纹和 MT6701 测量零点。校准有效/模型/指纹三个字段只读，固件事务管理；手工改零偏会使校准失效。当前 BMI088 零偏仍绑定原 `*_6050` 字段名，保持既有测量轴映射。

所有标记 `ParameterEffect::Reboot` 的参数仅能在锁定状态下保存。成功保存不同值后，统一参数服务锁存“待重启”状态：OLED 全屏显示英文 `REBOOT REQUIRED`，禁止解锁并保持执行器安全位置；改回原值也不会解除，只有重启清除。重复保存相同值、无效值或保存失败不触发。EEPROM、SD 与校准批量保存均使用同一提交入口检查生效标记。

新增其他重启参数时，使用它的模块也需要像 `aircraft_config.cpp` 一样锁定启动值，不能在控制周期直接使用可修改变量。

## EEPROM 与 SD 的区别

SD 通过文件系统读写文件；Teensy 4.1 的 EEPROM 接口使用固定逻辑地址，底层由芯片 Flash 仿真。两者均不应在控制循环每周期读取持久存储：开机加载到 RAM，控制运算只读 RAM；仅用户保存或校准时写入。

EEPROM 使用两个 2048 字节槽，起始地址 128 和 2176，要求 `EEPROM.length() >= 4224`。每槽头部 24 字节，剩余 **2024 字节**存放变长文本记录；容量由实际名称及数值长度决定，不能用固定条目数表示。保存前检查总长度，容量不足不改旧槽。0～127 不使用，当前两个槽的地址保持不变。

槽头保存格式版本、条目数、有效长度、递增代次、CRC32 和提交标记。EEPROM V3 与 SD V5 的每条记录完全相同：`名称:类型=值\n`，例如 `aircraft_id:int=1`。两者共用 `include/parameter_record.h` 的编码、数字解析和数值验证；类型为 `float` / `int`，浮点使用可恢复 float32 的普通十进制。没有记录 ID、删除状态或逐项代次。CRC 覆盖槽头有效字段及全部记录。

写入流程为：使备用槽无效 → 写入内容并逐字节读回 → 最后写提交标记 → 全部读回校验。只有新槽完整有效才切换；旧槽保持可恢复。启动选择最新有效槽；最新槽损坏则退回另一个槽。两个槽都无效才使用默认值，身份变成未配置，校准失效。未变化的内容不重复写入。

参数表变化并不等于整槽失效：槽的格式/CRC 合法后，逐项以名称、类型和当前范围恢复。新项或不兼容项单独使用默认值。整个存储格式版本不识别或两个槽均损坏，才全表回退。

SD 使用 `params.cfg` 主文件与 `params_backup.cfg` 回退文件，V5 文件包含固定板卡 UID、硬件/算法配置、代次、条目数、名称/类型/值和 CRC32。验证完整文件后再加载，验证完整新文件后才确认保存。板卡 UID 避免误用另一块板卡的卡；修改飞机编号或数量不会使同一板卡的调参丢失。

## 当前占用与容量

以下按当前默认值、当前 TEAM/INDI/EXP 配置及一位数代次计算，不是板上已保存数值的实测：

| 介质 | 当前参数数 | 单份有效数据 | 容量上限 |
| --- | ---: | ---: | --- |
| EEPROM | 18 | 471 字节记录 + 24 字节槽头 = 495 字节 | 每槽 2048 字节，其中记录可用 2024 字节 |
| SD | 57 | 1457 字节记录 + 83 字节文件头/CRC = 1540 字节 | 每文件小于 103168 字节 |

总计 75 项，一份完整参数数据为 2035 字节；两份快照/主备文件约 4070 字节。实际长度随保存值及 SD 代次位数变化，EEPROM 两槽仍固定预留 4096 字节。Teensy 4.1 当前 EEPROM 库暴露 4284 字节；0～127 与 4224～4283 未被参数槽使用。

按当前参数名及数值缓冲上限保守估计，18 项 EEPROM 记录不超过 1327 字节，连槽头不超过 1351 字节；不包含跨介质迁移尚未确认的额外源记录。当前默认记录距离 2024 字节上限还有 1553 字节。条目变长，容量按字节检查，不规定固定参数项数。

SD 的每文件缓冲为 `512 * (128 + 64 + 9) + 256 = 103168` 字节，最多可读写 103167 字节的文件；该缓冲同时占用 100.75 KiB 静态 RAM。全参数表上限为 512 项，包含两种介质的总数。这个软件处理限制与 SD 卡本身容量无关；飞行日志另按卡上剩余空间增长。

## 格式与介质迁移

仅支持当前 EEPROM V3 和 SD V5。当前格式没有有效快照时使用默认值，需要设置编号、数量和完成校准。

改存储介质后，从当前目标介质优先读取；目标尚无对应项时可读取原介质。先保存并验证目标，再重建原 EEPROM 快照以移除迁移副本。SD 保存失败时，EEPROM 中的源记录继续保留，仍占用容量；没有删除状态。容量不足或迁移失败不会静默丢弃旧项，需处理 `EEPROM_ERROR` / `MIGRATION_PENDING`。

统一的是参数记录和处理规则，外层保护适配介质：SD 保留板卡配置头、主/备文件及 CRC 尾；EEPROM 保留槽头及最后提交标记。代次用于选最新完整快照，CRC 用于识别损坏，提交标记用于确认写入完成，因此继续保留。

SD 拥有的校准字段缺失时，已经移除的 EEPROM 源记录不能证明当前校准有效。跨介质校准事务先保存 `valid=0`，再保存全部零偏及模型，最后保存 `valid=1`。整组指纹同时校验全部零偏和模型，SD 回退到旧备份导致混合新旧组时，校准失效。中途断电可恢复旧的完整校准，或保持无效状态，不能把混合的新旧数据当成有效校准。

EEPROM 写入和 SD 写入都可能阻塞；身份/校准修改要求锁定。本版没有在真机测量所有构型的最坏周期时间；统一固件会保留所有机型分支，代码体积增加，少量 RAM 判断开销需要板上检查 500 Hz 时序。

主机验证见 [存储测试](../tests/parameter_storage/README.md)。
